# 数据备份与恢复

代码仓库不能代替数据库与媒体备份。

## 一份可恢复备份应包含

1. 数据库一致性备份：包含证书编号、商品、用户、订单、图片路径与必要配置。
2. 媒体：Windows 的公开与私有照片／证据图／视频；Linux 系统 OSS 对象及原始对象 key。
3. 应用：与数据库版本对应的 JAR、前端产物、小程序版本记录和源码提交号。
4. 配置：数据库、OSS、微信、支付等机密配置，单独加密保存。
5. 清单：备份时间、文件数、总大小、SHA256、数据库版本、表引擎与备份命令。

## 一致性

此前证书库检查出现 MyISAM 表。`mysqldump --single-transaction` 不能单独保证 MyISAM 与其他表的一致性；应在维护窗口协调停写／锁表或使用经验证的一致性备份方式。不要直接复制正在运行的 MySQL 数据目录当作可靠逻辑备份。

长时间上传媒体期间业务可能继续写入，需要对齐数据库备份时间并做最终增量检查。网盘显示“传输完成”只证明队列完成，不代表数据库和所有媒体已一致性验收。

## 恢复顺序

1. 在隔离环境配置相同的数据库主版本及应用运行时。
2. 导入一致性数据库备份。
3. 恢复媒体到原路径/OSS key，保持编号目录结构；不要只按图片顺序推测关联。
4. 配置域名、凭据、私有路径及权限，禁用外部支付、短信、同步等真实写入。
5. 启动对应代码版本，抽查主图、证据图、视频、证书编号、订单和钱包汇总。
6. 核对全量“数据库路径有值但文件不存在”清单；空路径、文件缺失、权限错误、无法读取应分别统计。
7. 通过验收后再安排生产切换。

旧照片丢失不会因为导入源码恢复。网盘恢复素材需先按证书编号、原路径、文件哈希等核对，再制定回填清单。
